# Kubernetes fault injection record

- Time: 2026-08-31 (Asia/Shanghai)
- Cluster: Docker Desktop kubeadm, Kubernetes v1.36.1
- Namespace: `food-master`
- Target: `food-master-trade`

## Procedure

The trade HPA target was temporarily changed so it would not immediately restore the replica. The trade Deployment was then scaled to zero. After the checks, the Deployment and HPA target were restored.

```powershell
kubectl -n food-master patch hpa food-master-trade --type=merge -p '{"spec":{"scaleTargetRef":{"apiVersion":"apps/v1","kind":"Deployment","name":"food-master-trade-paused"}}}'
kubectl -n food-master scale deployment/food-master-trade --replicas=0
kubectl -n food-master wait --for=delete pod -l app.kubernetes.io/name=food-master-trade --timeout=120s
```

## Observed outage

There were no trade Pods. A request from the BFF Pod through the Nginx service returned the designed fallback:

```text
HTTP status: 503
{"error":"dependency service temporarily unavailable","fallback":true}
```

At the same time, the unaffected endpoints returned:

```text
user-service:      HTTP 200 {"status": "ok", "service": "user-service"}
lifestyle-service: HTTP 200 {"status": "ok", "service": "lifestyle-service"}
BFF readiness:     HTTP 200 {"status": "ready", "service": "food-master"}
```

## Recovery

```powershell
kubectl -n food-master scale deployment/food-master-trade --replicas=1
kubectl -n food-master patch hpa food-master-trade --type=merge -p '{"spec":{"scaleTargetRef":{"apiVersion":"apps/v1","kind":"Deployment","name":"food-master-trade"}}}'
kubectl -n food-master rollout status deployment/food-master-trade --timeout=180s
```

After rollout, the trade health endpoint returned:

```text
HTTP 200 {"status": "ok", "service": "trade-service"}
```

## Conclusion

The injected trade-service outage remained isolated to the trade route. Nginx returned the designed 503 response, unrelated services stayed healthy, and both the Deployment and HPA were restored after the experiment.
