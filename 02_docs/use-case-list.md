# 本地生活服务平台业务场景（用例）清单

## 1. 清单说明

本清单按“参与者为完成一个明确业务目标而经历的完整流程”划分用例。搜索、排序、查看详情、点击按钮、修改购物车数量、查询订单状态等单一步骤不单独作为用例，而是并入其服务的完整业务流程。



## 2. 参与者

| 参与者 | 说明 |
| --- | --- |
| 游客 | 尚未登录的访问者，可注册普通用户、骑手或商家账号 |
| 普通用户 | 搜索和购买本地生活服务、查看个人订单、评价、发布内容、使用 AI 助手 |
| 骑手 | 接受外卖配送任务并推进取餐、送达状态 |
| 商家 | 发布美食、酒店和娱乐场所，管理菜品状态，处理外卖备餐和团购券核销 |
| 管理员 | 维护用户和角色、处理异常订单、审核博客与评论 |
| 外部 AI 服务 | 根据平台商品信息与用户历史提供咨询回复 |

## 4. 详细用例说明

### UC01 建立账号并进入角色工作台

- **参与者：** 游客；管理员账号由系统预置，不开放自助注册。
- **触发条件：** 游客希望以普通用户、骑手或商家身份使用平台。
- **前置条件：** 平台可访问；游客未处于有效登录会话。
- **后置条件：** 新账号被保存；登录成功后生成会话，并进入与账号角色匹配的工作台。
- **主成功流程：**
  1. 游客填写用户名、密码、手机号并选择普通用户、骑手或商家身份。
  2. 系统校验必填项、密码强度、手机号格式和用户名唯一性。
  3. 系统创建账号并跳转登录页。
  4. 用户输入用户名、密码并选择与账号一致的身份。
  5. 系统建立会话：普通用户和商家进入美食页，骑手进入订单中心；预置管理员进入管理后台。
  6. 用户退出后会话被清除并返回首页。
- **备选/异常流程：** 用户名重复、密码不满足 8-16 位且同时包含字母和数字、手机号格式错误或角色非法时拒绝注册；用户名不存在、密码错误、登录身份不匹配或账号已停用时拒绝登录；游客直接访问受限页面时返回首页或登录页。
- **可验证结果：** `User` 记录的角色和状态正确；会话含当前用户编号；不同角色的跳转地址正确；停用账号无法登录；退出后旧会话不可继续使用。
- **实现入口：** `myapp.views.register`、`myapp.views.login`、`myapp.views.logout_view`、`myapp.admin_views.admin_required`。
- **现有测试证据：** `test_register_login_and_role_redirects`、`test_role_permissions_are_enforced`、`test_admin_dashboard_and_actions`。
- **追溯编号：** `SYS-SEQ01 / COMP-SEQ01 / OBJ-SEQ01 / UNIT-TC01 / INT-TC01 / E2E-TC01`。

### UC02 完成外卖下单、配送履约与评价

- **参与者：** 普通用户（主）、骑手、商家。
- **触发条件：** 普通用户提交外卖订单；订单生成后，骑手接受配送任务并与商家共同完成履约。
- **前置条件：** 三类参与者均已登录；菜品存在、未下架且未售罄；菜品归属一个商家。
- **后置条件：** 订单按 `0 -> 1 -> 2 -> 3 -> 4 -> 5` 完成流转，菜品评分、配送评分和评价被保存。
- **主成功流程：**
  1. 用户通过列表、搜索、排序和详情页选择菜品，填写数量及配送地址并直接下单。
  2. 系统计算订单金额，创建“待骑手接单”订单（`pos=0`），并在相关角色页面展示。
  3. 骑手在订单中心接单，系统绑定骑手并将状态改为 `pos=1`。
  4. 所属商家确认完成备餐，系统将状态改为 `pos=2`。
  5. 已绑定骑手确认取餐，系统将状态改为 `pos=3`。
  6. 骑手确认送达，系统将状态改为 `pos=4`。
  7. 用户在个人中心查看订单，提交菜品评分、配送评分和评价，系统将状态改为 `pos=5`。
- **备选流程：** 用户可先将一个或多个菜品加入购物车，修改数量/地址、删除条目，再统一结算；系统为每个有效购物车条目创建订单并清空购物车。
- **异常流程：** 菜品不存在、已下架或售罄时拒绝下单；信息不完整或数量非法时拒绝创建；购物车包含不可售菜品时整体拒绝结算；订单已被其他骑手接走时接单失败；非所属商家、非绑定骑手、错误状态或错误角色不能推进订单；评分不在 `(0, 5]` 或评价超过 200 字时拒绝提交。
- **可验证结果：** 订单金额、用户、菜品、地址和骑手正确；每个状态只能由对应角色在合法前态推进；三类角色看到一致的订单数据和允许操作；最终评分、评价及 `pos=5` 可查询。
- **实现入口：** `food`、`fooddetails`、`foodorder`、`update_cart_item`、`delete_cart_item`、`clear_cart`、`rider_orders`、`rider_accept`、`merchant_prepare`、`rider_get`、`rider_deliver`、`orderpos`、`ordercomment`。
- **现有测试证据：** `test_food_order_full_delivery_and_review_flow`、`test_cross_role_food_order_visibility_and_response_flow`、`test_food_listing_search_detail_order_status_and_space_queries`、`test_role_permissions_are_enforced`。
- **追溯编号：** `SYS-SEQ02 / COMP-SEQ02 / OBJ-SEQ02 / UNIT-TC02 / INT-TC02 / E2E-TC02`。

### UC03 购买并核销到店团购券

- **参与者：** 普通用户（主）、商家。
- **触发条件：** 用户希望购买菜品对应的到店团购服务。
- **前置条件：** 用户已登录；菜品存在、未下架且未售罄；菜品归属商家。
- **后置条件：** 团购券由“待使用”变为“已使用”，并记录核销时间。
- **主成功流程：**
  1. 用户从菜品详情进入团购下单，填写正整数数量。
  2. 系统计算总价，生成全局唯一核销码并创建 `status=0` 的团购券。
  3. 用户在个人中心查看核销码和待使用状态。
  4. 所属商家在个人中心查看该券并输入核销码。
  5. 系统验证券归属和状态，将其改为 `status=1` 并记录 `used_at`。
  6. 用户再次查看时看到已使用状态。
- **备选/异常流程：** 数量为空、非整数或不大于 0 时拒绝创建；非商家不能核销；核销码为空、不存在或不属于当前商家的商品时拒绝；已使用或已取消的券不能再次核销。
- **可验证结果：** 团购券数量、总价、用户、菜品、唯一核销码和状态正确；只有所属商家能核销；成功核销后时间非空且用户端状态同步。
- **实现入口：** `groupbuyorder`、`make_group_buy_code`、`groupbuy_redeem`、`space`。
- **现有测试证据：** `test_group_buy_coupon_create_display_and_redeem_flow`。
- **追溯编号：** `SYS-SEQ03 / COMP-SEQ03 / OBJ-SEQ03 / UNIT-TC03 / INT-TC03 / E2E-TC03`。

### UC04 预订酒店并评价入住体验

- **参与者：** 普通用户。
- **触发条件：** 用户选择酒店并希望预订指定房型和入住时段。
- **前置条件：** 用户已登录；酒店存在；所选房型已配置价格。
- **后置条件：** 酒店订单被创建并可评价；评价后订单为已评价，酒店平均评分和评分人数更新。
- **主成功流程：**
  1. 用户通过列表、搜索、排序和详情页选择酒店。
  2. 用户填写房型、入住时间和入住时长。
  3. 系统按房型单价乘以时长计算总价并创建 `pos=4` 的酒店订单。
  4. 用户在个人中心查看本人酒店订单和待评价状态。
  5. 用户提交 `(0, 5]` 范围的评分及不超过 200 字的评价。
  6. 系统将订单改为 `pos=5`，重新计算酒店平均评分和评分人数。
- **备选/异常流程：** 酒店或房型不存在、信息不完整、时长不是正整数、入住时间格式错误时拒绝创建；非订单本人不能查看或评价；评分非法或评价过长时拒绝保存。
- **可验证结果：** 房型、入住时间、时长和金额正确；只有本人能查看和评价；评价后订单状态、评分、评价、酒店均分和评分人数一致。
- **实现入口：** `hotel`、`hoteldetails`、`hotelorder`、`hotelorderpos`、`hotelcomment`、`save_hotel_review`、`update_hotel_rating`。
- **现有测试证据：** `test_hotel_booking_and_review_flow`、`test_hotel_listing_search_detail_order_status_and_permissions`。
- **追溯编号：** `SYS-SEQ04 / COMP-SEQ04 / OBJ-SEQ04 / UNIT-TC04 / INT-TC04 / E2E-TC04`。

### UC05 购买娱乐门票并评价体验

- **参与者：** 普通用户。
- **触发条件：** 用户选择娱乐场所并希望购买指定日期和数量的门票。
- **前置条件：** 用户已登录；娱乐场所存在且配置了票价。
- **后置条件：** 门票订单被创建并可评价；评价后订单为已评价，场所平均评分和评分人数更新。
- **主成功流程：**
  1. 用户通过列表、搜索、排序和详情页选择娱乐场所。
  2. 用户填写游玩时间和正整数票数。
  3. 系统按票价乘以数量计算总价并创建 `pos=4` 的门票订单。
  4. 用户在个人中心查看本人门票订单和待评价状态。
  5. 用户提交评分和评价。
  6. 系统将订单改为 `pos=5`，重新计算场所平均评分和评分人数。
- **备选/异常流程：** 场所不存在、信息不完整、票数不是正整数或游玩时间格式错误时拒绝创建；非订单本人不能查看或评价；评分非法或评价过长时拒绝保存。
- **可验证结果：** 游玩时间、票数和金额正确；只有本人能查看和评价；订单与场所评分统计同步更新。
- **实现入口：** `play`、`playdetails`、`playorder`、`playorderpos`、`playcomment`、`save_play_review`、`update_play_rating`。
- **现有测试证据：** `test_play_ticket_order_and_review_flow`、`test_play_listing_search_detail_order_status_and_permissions`。
- **追溯编号：** `SYS-SEQ05 / COMP-SEQ05 / OBJ-SEQ05 / UNIT-TC05 / INT-TC05 / E2E-TC05`。

### UC06 发布并维护商家服务供给

- **参与者：** 商家。
- **触发条件：** 商家希望在平台上线新的美食、酒店或娱乐场所，或调整菜品可售状态。
- **前置条件：** 商家账号已登录且未停用。
- **后置条件：** 新供给记录归属当前商家并在对应列表显示；菜品下架/上架或售罄/恢复状态生效。
- **主成功流程：**
  1. 商家选择发布美食、酒店或娱乐场所。
  2. 商家填写该类型的必填业务字段并上传 JPG/PNG 图片。
  3. 系统校验字段、价格、营业时间和图片类型/大小，将图片保存并创建归属当前商家的记录。
  4. 新供给在对应列表和商家个人中心显示。
  5. 对于菜品，商家可在个人中心切换售罄状态或上下架状态。
  6. 系统据此允许或阻止用户查看、下单及购物车结算。
- **备选/异常流程：** 非商家访问时拒绝；必填字段缺失、价格非法、营业时间格式非法、图片缺失、非 JPG/PNG 或超过 2 MB 时拒绝创建；商家不能维护其他商家的菜品；不支持的状态操作被拒绝。
- **可验证结果：** 新记录字段和商家外键正确；图片路径可用；列表及个人中心可见；菜品状态切换后用户侧限制同步生效。
- **实现入口：** `foodsend`、`hotelsend`、`playsend`、`merchant_food_action`、`food`、`space`。
- **现有测试证据：** `test_merchant_can_create_food_hotel_and_play_with_uploads`、`test_role_permissions_are_enforced`。
- **追溯编号：** `SYS-SEQ06 / COMP-SEQ06 / OBJ-SEQ06 / UNIT-TC06 / INT-TC06 / E2E-TC06`。

### UC07 发布内容并参与社区互动

- **参与者：** 普通用户（作者或读者）。
- **触发条件：** 用户希望分享本地生活内容，或阅读并评论其他用户的内容。
- **前置条件：** 用户已登录。
- **后置条件：** 博客或评论被发布并可见；本人删除后记录被逻辑删除且不再公开显示。
- **主成功流程：**
  1. 作者填写标题和正文并发布博客。
  2. 系统保存作者和发布时间，博客进入公开列表。
  3. 读者通过列表或关键字搜索进入详情并查看未删除评论。
  4. 读者提交不超过 500 字的非空评论，系统保存评论者和时间。
  5. 博客作者可删除本人博客；评论者可删除本人评论。
  6. 系统逻辑删除目标内容，并从公开查询中排除。
- **备选/异常流程：** 标题或正文为空时拒绝发布；评论数据非法、博客不存在、内容为空或过长时拒绝评论；未登录、非作者或非评论者不能删除；已删除或不存在的博客不可查看。
- **可验证结果：** 博客作者、评论用户、正文和时间正确；搜索和详情可见；越权删除失败；逻辑删除标志更新且公开列表不再显示。
- **实现入口：** `blog`、`blogsend`、`blogsdetails`、`blogcomment`、`delete_blog`、`delete_comment`。
- **现有测试证据：** `test_blog_comment_and_delete_flow`、`test_blog_listing_detail_and_search_queries`。
- **追溯编号：** `SYS-SEQ07 / COMP-SEQ07 / OBJ-SEQ07 / UNIT-TC07 / INT-TC07 / E2E-TC07`。

### UC08 获取个性化 AI 咨询

- **参与者：** 普通用户（主）、外部 AI 服务。
- **触发条件：** 用户希望根据平台当前供给和自己的历史偏好获得推荐或答疑。
- **前置条件：** 用户已登录；AI 服务配置有效；平台存在可读取的商品和用户数据。
- **后置条件：** 页面得到结构化回复；用户订单历史和当前可售供给仅作为本次模型上下文使用。
- **主成功流程：**
  1. 用户在任一主要页面的 AI 助手中输入非空问题。
  2. 系统读取用户简介和外卖订单历史。
  3. 系统从缓存读取或重新生成当前美食、酒店和娱乐场所摘要。
  4. 系统组合个性化提示并调用外部 AI 服务。
  5. AI 服务返回结果，系统以 JSON 回复并在页面持续展示对话。
- **备选/异常流程：** 未登录时返回首页；输入为空时返回 400；外部服务无响应时返回 500 和暂不可用提示；缓存失效时重新生成平台上下文。
- **可验证结果：** 成功响应含 `reply`；调用提示包含当前用户及平台供给；失败响应状态和提示可识别；下架或售罄菜品不进入新的全局上下文。
- **实现入口：** `ai_chat_view`、`get_global_info`、`myapp.utils.llm_client.call_aliyun_llm`。
- **现有测试证据：** `test_ai_chat_endpoint_uses_catalog_context_without_live_network`（外部调用已 mock）。
- **追溯编号：** `SYS-SEQ08 / COMP-SEQ08 / OBJ-SEQ08 / UNIT-TC08 / INT-TC08 / E2E-TC08`。

### UC09 开展平台运营治理

- **参与者：** 管理员。
- **触发条件：** 管理员发现用户账号、外卖订单或社区内容需要治理。
- **前置条件：** 未停用的管理员账号已登录管理后台；目标用户、订单、博客或评论存在。
- **后置条件：** 目标用户的状态或角色、订单的异常标记或状态、社区内容的公开状态被更新。
- **主成功流程：**
  1. 管理员进入管理后台，查看平台统计和近期订单。
  2. 管理员进入用户、订单或内容管理区，通过关键字定位目标。
  3. 管理用户时，管理员停用、启用账号或调整普通用户、骑手、商家、管理员角色。
  4. 处理订单时，管理员切换异常标记，或将卡住的未完成订单标记为已送达 `pos=4`。
  5. 审核内容时，管理员隐藏或恢复目标博客、评论。
  6. 系统校验操作，保存变更并在管理后台反馈结果。
